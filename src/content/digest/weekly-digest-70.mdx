## 🎨 Проверка CSS

### Вышли Stylelint 18 и Stylistic 6

[Stylelint 18.0.0](https://github.com/stylelint/stylelint/releases/tag/18.0.0) точнее проверяет значения CSS, в том числе записанные через `var()`. Перед обновлением стоит свериться с [руководством по переходу на Stylelint 18](https://stylelint.io/migration-guide/to-18/): изменились требования к Node.js и некоторые параметры командной строки.

В [`@stylistic/stylelint-plugin` 6.0.0](https://github.com/stylelint-stylistic/stylelint-stylistic/releases/tag/v6.0.0) обновили правила оформления стилей. Например, правило, которое ограничивает число объявлений в одной строке, переехало из Stylelint в плагин. Отдельный пакет [`@stylistic/stylelint-config` 6.0.0](https://github.com/stylelint-stylistic/stylelint-config/releases/tag/v6.0.0) тоже требует Stylelint 18 и включает настройки для SCSS и Less.

Плагин нужно обновлять вместе со Stylelint:

```bash
pnpm up @stylistic/stylelint-plugin@latest stylelint@latest
```

После обновления проверьте свою конфигурацию по [руководству по переходу на Stylistic 6](https://stylelint-stylistic.github.io/migration-guide/to-6.0.0). Например, для SCSS и Less в правилах теперь используются отдельные префиксы. Если удобнее начать с готового набора правил оформления, добавьте [встроенный пресет `@stylistic/stylelint-plugin/recommended`](https://stylelint-stylistic.github.io/user-guide/configs) в поле `extends`.

Спасибо firefoxic за новость о релизах Stylelint и Stylistic!

## 🧪 HTML и веб-платформа

### Safari пробует автоматически затемнять сайты

В бета-версии Safari 27.3 можно включить [адаптивную тёмную тему](https://webkit.org/blog/18541/introducing-adaptive-dark-mode/). Когда у сайта есть только светлое оформление, браузер сам подбирает тёмные цвета. По данным WebKit, около 40% загрузок страниц приходится на пользователей с тёмным режимом, а собственную тёмную тему страницы используют примерно в 10% загрузок.


- В [бета-версии Chrome 158](https://chromestatus.com/release-notes/158) тестируют элемент `<install>` для установки веб-приложений и CSS-состояния `:playing` и `:paused` для медиа. Отдельный сайт отслеживает [вывод XSLT из браузеров](https://xslt.rip/). Эту технологию используют, чтобы преобразовывать XML, например в HTML.
- Рэйчел Эндрю собрала [октябрьские изменения веб-платформы](https://web.dev/blog/web-platform-10-2026?hl=en). Среди них поддержка анимаций, привязанных к прокрутке, во всех основных браузерных движках.
- Мисти Де Мео объясняет, [как сохранить копию сайта](https://blog.mistys-internet.website/post/2026/10/29/if-you-love-a-website-back-it-up/), если он может исчезнуть. В статье есть способы сделать снимок страницы прямо в браузере, автоматически обойти ссылки и встроить получившийся архив.

- Крис Койер собрал [колонки, которые движутся с разной скоростью при прокрутке](https://blog.master.dev/multi-column-different-speed-scrolling/). Их движение зависит от позиции на странице через CSS-анимации.

## 🔒 Безопасность веба

### Как сторонний скрипт превратился в атаку на Polymarket

Скотт Хелм разобрал [подмену скрипта мониторинга Polymarket](https://blog.report-uri.com/polymarkets-csp-allowed-every-part-of-the-2-6-million-crypto-theft/). Как и в [случае с забытыми тегами `<script>`](https://blog.report-uri.com/deadtag-how-forgotten-website-tags-became-a-delivery-network-for-iphone-spyware/), сайт продолжал доверять внешнему ресурсу, когда тот уже стал опасным. Браузер загрузил код с уже разрешённого адреса, но файл по этому адресу изменился. Политика безопасности CSP пропустила запрос, потому что источник остался прежним.

Для статичных файлов можно задать [контрольную сумму через Subresource Integrity](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Subresource_Integrity). Тогда браузер проверяет, что получил именно ту версию, которую указал сайт. Заголовок [`Integrity-Policy-Report-Only`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Integrity-Policy-Report-Only) помогает сначала собрать отчёты о ресурсах без такой проверки.

- [Request Map](https://requestmap.webperf.tools/) помогает увидеть, какие адреса запрашивает страница, а [Third Party Web](https://www.thirdpartyweb.today/) показывает типичную нагрузку от сторонних сервисов. Чтобы уменьшить влияние на интерфейс, можно [изменить порядок загрузки стороннего JavaScript](https://web.dev/articles/optimizing-content-efficiency-loading-third-party-javascript) или вынести подходящие скрипты в отдельный поток с [Partytown](https://partytown.qwik.dev/).
- В исследовании [скриптов для распознавания браузеров по Canvas](https://nullpt.rs/fingerprinting-bioweapons) нашли код со скрытыми символами Unicode. В них спрятали инструкции, рассчитанные на то, чтобы ИИ отказывался разбирать скрипт. [Fingerprint Garden](https://fingerprint.garden/) показывает найденные примеры, а [BrowserLeaks](https://browserleaks.com/canvas) демонстрирует, какие особенности отрисовки позволяют различать браузеры.

## 📦 JavaScript, среды выполнения и WebAssembly

### Экспериментальный движок djs сохраняет состояние работающего скрипта

Армин Ронахер, создатель [Flask](https://flask.palletsprojects.com/en/stable/), представил [движок JavaScript djs](https://github.com/earendil-works/djs), который работает в WebAssembly. Он умеет сохранить состояние виртуальной машины и продолжить выполнение в другой среде. Остановиться можно даже там, где код ждёт результат через `await`. Такой подход позволяет перенести незавершённую задачу вместе с её состоянием.

- Бартош показал [как собрать строки и запустить JavaScript без кавычек и круглых скобок](https://blog.ikaes.de/generating-strings-without-parentheses-in-javascript/). Это головоломка про синтаксис и неявное преобразование значений.
- В Cloudflare Workers можно [включить встроенный Temporal](https://developers.cloudflare.com/workers/configuration/compatibility-flags/#enable-the-temporal-api) флагом совместимости. API помогает работать с датами, временем и часовыми поясами. Для дат совместимости с 1 декабря его планируют включить по умолчанию.
- Команда Microsoft объясняет, [как уменьшила размер `clarity.js` после сжатия](https://clarity.microsoft.com/blog/how-we-made-clarity-js-smaller/). Удаление импортов вида `import *` помогло, а вынос повторяющегося кода в функции иногда давал более крупный файл. Статья показывает, почему размер исходника и размер загрузки стоит измерять отдельно.
- Сергей Целовальников сравнил, [какие символы считаются пробельными в Java, Python и JavaScript](https://serce.me/posts/2026-10-30-how-hard-is-it-to-check-for-whitespace). Для обычного пробела языки согласны, но некоторые символы Unicode дают разные результаты.
- Кейт Холтерхофф объясняет, [зачем вебу несколько сред выполнения JavaScript](https://redmonk.com/kholterhoff/2026/10/27/js-runtime-monoculture/). Выбор между движками и средами влияет на то, какие возможности получает разработчик и насколько легко перенести приложение.
- Николя Шарпантье разобрал [пробел в предупреждениях Dependabot для Bun](https://charpeni.com/blog/the-bun-dependabot-gap-dependabot-alerts-dont-see-bun-lock). Если GitHub не читает `bun.lock`, часть зависимостей, которые подтянулись автоматически, остаётся вне поля зрения.
- [Handwired](https://chenglou.me/handwired/) превращает JavaScript в сеть математических операций, которую можно запустить на GPU. Автор [Pretext](https://chenglou.me/pretext/) показал на этом подходе поиск по 100 тысячам JSON-документов.
- [CheerpJ 5.0](https://labs.leaningtech.com/blog/cheerpj-5.0) позволяет запускать Java 21 и 25 в браузере с помощью WebAssembly. В комплект входит JDK, поэтому код можно даже скомпилировать во вкладке.
- Джеймс Лонг [возвращает к жизни Prepack](https://jamesbox.exe.xyz/artifacts/prepack-revived/), инструмент, который выполняет часть JavaScript заранее. В [демо с React](https://jamesbox.exe.xyz/northstar/prepack/) можно сравнить время серверной отрисовки обычным React, результатом Prepack и сочетанием обоих подходов.

## ⚛️ React и фреймворки

### Redux Toolkit готовится к версии 3.0

Марк Эриксон опубликовал [план развития Redux Toolkit](https://github.com/reduxjs/redux-toolkit/discussions/5536). В 3.0 команда собирается оставить только стандартные модули JavaScript (ESM). Проектам, которые загружают библиотеку через `require()`, понадобится проверить способ подключения.

### В Next.js экспериментируют с обработчиками маршрутов на Go

В [прототипе Next.js](https://github.com/vercel/next.js/pull/100130) серверный маршрут можно описать в файле `route.go`. Из него экспортируют обработчики HTTP-методов, например `GET`, а Turbopack компилирует код для отдельного процесса на Go. Пока это эксперимент для App Router.

- В [ноябрьском обновлении безопасности Next.js](https://nextjs.org/blog/november-2026-security-release) закрыли семь уязвимостей, в том числе в Cache Components. Исправления выпустили в ветках 16.4.5 и 15.5.29.
- Vercel [переносит Data Cache приложений Next.js в Runtime Cache](https://vercel.com/blog/simplifying-runtime-caching-on-vercel). Меняются лимиты хранилища и тарификация чтения и записи. В [графике перехода](https://vercel.com/changelog/data-cache-is-moving-to-runtime-cache) даты и условия разбиты по тарифам.
- Александр Тротель в [разборе внутреннего устройства React](https://www.alexandretrotel.org/articles/understanding-react-internals) начинает с сервера и доходит до дерева Fiber, приоритетов обновлений и этапа, на котором React применяет изменения к странице.
- Харрисон Милбрадт рассказывает, [почему его команда перешла с Next.js на TanStack Start](https://harrisonmilbradt.com/writing/nextjs-to-tanstack-start). Последним аргументом стали утечки памяти, которые команда обнаружила в двух версиях Next.js 16.3 на работающем сервисе.
- Корбин Кратчли показывает, [как сохранить правки пользователя при повторной загрузке данных](https://playfulprogramming.com/posts/writable-derived-state). Если хранить отдельно черновик и ответ сервера, значение для формы можно вычислить как `clientData ?? serverData` без синхронизации через `useEffect`.
- [Skullet](https://skullet.lochie.me) строит заглушку по размерам настоящего компонента, чтобы интерфейс меньше прыгал при появлении данных. В [документации](https://skullet.lochie.me/docs) есть примеры подключения, а в [разборе работы](https://skullet.lochie.me/docs#how) показано, как инструмент измеряет скрытый компонент.
- В [react-resizable-panels 4.16](https://github.com/bvaughn/react-resizable-panels/releases/tag/4.16.0) появился `Workspace` с перетаскиваемыми вкладками. Вкладка сохраняет состояние при переносе в другую панель. Поведение можно проверить в [демо рабочего пространства](https://react-resizable-panels.vercel.app/examples/workspace).

### Обновления

- В [Vitest 5.1](https://vitest.dev/blog/vitest-5-1) флаг `--since-last-run` повторно запускает тесты, затронутые правками с прошлого запуска. Vitest запоминает, какие файлы загружал каждый тест. Ещё добавили интерактивный просмотр изменений сохранённых результатов тестов.
- [Rspack 2.3](https://rspack.rs/blog/announcing-2-3) перешёл на [SWC Next](https://github.com/swc-project/swc-next), обновлённый инструмент разбора JavaScript. По замерам команды, сборки стали быстрее на 5–20%, а пиковое потребление памяти снизилось.
- В [первой бете Leaflet 2.0](https://github.com/Leaflet/Leaflet/releases/tag/v2.0.0-beta.1) у библиотеки карт появились встроенные типы TypeScript. Сборщик теперь может удалить неиспользуемый код, а импорт по умолчанию заменили именованными импортами.
- В [ESLint 10.14](https://eslint.org/blog/2026/10/eslint-v10.14.0-released/) исправили пограничные случаи в нескольких правилах, включая `no-invalid-this` и `object-shorthand`.
- В [Shiki 4.6](https://shiki.style/) ускорили обработку дополнительных стилей подсветки и уменьшили размер модуля WebAssembly, который ищет совпадения по регулярным выражениям.
- [jsdom 31.0](https://github.com/jsdom/jsdom/releases/tag/v31.0.0), который имитирует браузерный DOM в тестах, получил новую реализацию CSS с поддержкой вложенности, каскадных слоёв и `@scope`. Также изменилось подключение Canvas и поведение при разборе блокирующих скриптов.
- В [Vite+ 1.5](https://github.com/voidzero-dev/vite-plus/releases/tag/v1.5.0) добавили загрузчик TypeScript через `node --import vite-plus/register`. Его можно подключить к встроенному запуску тестов Node.js или к AVA.
- Вышла [первая бета Storybook 11](https://github.com/storybookjs/storybook/releases/tag/v11.0.0-beta.0). Storybook позволяет открывать компоненты отдельно от приложения и проверять, как они выглядят в разных состояниях.
