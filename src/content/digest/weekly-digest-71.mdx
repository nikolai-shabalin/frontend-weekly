## 🧪 HTML и веб-платформа

### Firefox 160 добавил распознавание речи прямо на устройстве

В стабильном [Firefox 160](https://developer.mozilla.org/en-US/docs/Mozilla/Firefox/Releases/160) на десктопе появилось распознавание речи без отправки аудио на сервер: его можно использовать через [Web Speech API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Speech_API/Using_the_Web_Speech_API#on-device_speech_recognition). Это полезно для голосового ввода и приложений, где важна приватность. В этой же версии за флагами можно проверить `blocking="render"` и отложенную загрузку аудио и видео.

### SVG готовится к связанным параметрам

Roman Komarov показал, как [linked parameters для SVG](https://blog.kizu.dev/link-parameters-soon/) позволят переиспользовать и связывать значения внутри векторной графики. Это может заметно упростить создание настраиваемых и интерактивных схем, иконок и иллюстраций без дублирования разметки.

- В эссе [«Веба более чем достаточно»](https://ftrain.com/aboard-the-web-is-more-than-enough) собраны возможности WebAssembly, Web Crypto, WebGL и Web Audio, с которыми браузер давно стал средой для серьёзных приложений.
- [Zigzag](https://zigzagbrowser.com) — очень компактный браузер для macOS: его размер заявлен всего в 18 МБ.
- [The Website Specification](https://specification.website/) помогает свериться с тем, что для сайта обязательно, что рекомендуется, а чего лучше избегать вне зависимости от выбранного стека.

## 🎨 CSS и дизайн

### Адаптивность нужно проверять не только в обычном viewport

В статье [Beyond the Viewport](https://ishadeed.com/article/beyond-the-viewport/) Ahmad Shadeed напоминает: реальный размер страницы меняют экранная клавиатура, split view, открытые DevTools и встроенные браузеры приложений. Его бесплатный [Site Seeing](https://lab.ishadeed.com/tools/site-seeing/) позволяет посмотреть макет в таких неудобных, но распространённых контекстах до того, как с ними столкнутся пользователи.

### CSS можно использовать для расчётов и диаграмм

Интерактивный материал [«Computing with CSS Layout»](https://noscript.ing/compute) показывает, как превратить особенности Grid, Flexbox и других механизмов раскладки в вычисления. Автор извлекает результаты этих «расчётов» обратно в числа и на их основе строит, например, анимированные графики.

В статье о [создании диаграмм современным CSS](https://blog.master.dev/creating-diagrams-and-graphs-using-modern-css/?utm_source=CSS-Weekly&utm_campaign=Issue-640&utm_medium=web) показано, как для простых статичных схем использовать anchor positioning, `border-shape`, `shape()` и `if()`. Это не замена библиотеке визуализации, но хороший способ не подключать JavaScript там, где нужна небольшая схема в интерфейсе.

### CSS научили замечать пересечение элементов

Ahmad Shadeed разобрал, как [определять пересечение двух элементов только средствами CSS](https://ishadeed.com/article/css-detect-overlap/?utm_source=CSS-Weekly&utm_campaign=Issue-640&utm_medium=web). Решение использует anchor positioning и scroll-driven animations: это открывает путь к эффектам, которые раньше обычно требовали `IntersectionObserver` и ручных вычислений в JavaScript.

### Новые приёмы для повседневного CSS

- Lea Verou предлагает [гибкий и поддерживаемый способ работы с иконками](https://lea.verou.me/blog/2026/icons/?utm_source=CSS-Weekly&utm_campaign=Issue-640&utm_medium=web), в котором CSS помогает не размазывать одинаковые настройки по компонентам.
- Техника [Using Declarations Just Once](https://css-tricks.com/css-using-declarations-just-once/) объединяет повторяющиеся CSS-объявления под одним селектором. Эксперимент с [css-dedup](https://github.com/j9t/css-dedup) на 30 сайтах показывает: размер не сжатого CSS иногда уменьшается заметно, но применять приём стоит выборочно.
- Функция [`random()` в CSS](https://www.smashingmagazine.com/2026/10/embracing-playful-imperfection-css-random-function/?utm_source=CSS-Weekly&utm_campaign=Issue-640&utm_medium=web) добавляет контролируемую неровность без генерации сотен строк препроцессором или JavaScript.
- Короткое введение в [CSS Layers](https://kittygiraudel.com/2026/11/01/playing-with-css-layers/?utm_source=CSS-Weekly&utm_campaign=Issue-640&utm_medium=web) пригодится, чтобы управлять приоритетом стилей без бесконечного роста специфичности.
- Rachel Andrew объясняет, почему рабочая группа CSS стремится делать [новые возможности универсальными](https://rachelandrew.co.uk/archives/2026/11/02/making-features-generic-in-css/), а не затачивать их под единственный сценарий.
- Temani Afif показывает, как [собрать поведение `:nth-child()` современными средствами CSS](https://css-tricks.com/re-implementing-nth-child-with-modern-css/), чтобы лучше понять работу селекторов.

- [Scroll-Triggered Animations Debugger](https://www.bram.us/2026/10/14/scroll-triggered-animations-debugger-devtools-extension/?utm_source=CSS-Weekly&utm_campaign=Issue-640&utm_medium=web) — расширение DevTools для наглядной отладки анимаций, запускаемых прокруткой.

## ♿ Доступность и UX

### Системные цвета нельзя считать автоматически контрастными

Aaron Gustafson обнаружил, что парные системные цвета вроде `Highlight` и `HighlightText` могут давать плохой контраст: в тёмной теме Chrome на Android — всего 1,98:1. В статье [«System Colors Need to Work Together»](https://www.aaron-gustafson.com/notebook/system-colors-need-to-work-together/) и сопутствующем [кроссбраузерном исследовании](https://aarongustafson.github.io/system-color-study/) есть конкретные пары, которые выдерживают проверку.

- [This Hue Shall Pass](https://thishueshallpass.clearleft.com/) проверяет все пары переднего плана и фона палитры по WCAG AA и AAA, а затем помогает довести близкий к проходному цвет до нужного контраста, не меняя его оттенок. О выборе цветовой коррекции авторы рассказывают [отдельно](https://clearleft.com/thinking/fix-the-contrast-without-losing-your-brand).
- GitHub теперь распознаёт файл [`ACCESSIBILITY.md`](https://github.blog/open-source/maintainers/accessibility-statements-now-have-a-home-on-github/) и показывает заявление о доступности на странице репозитория.
- Eric Bailey разбирает, как [сделать иммерсивные чаты с LLM доступнее](https://www.smashingmagazine.com/2026/11/making-immersive-llm-chat-experiences-more-accessible/): большие потоковые интерфейсы особенно нуждаются в ясном фокусе, корректных объявлениях состояния и управлении движением.
- [form-saver](https://github.com/aarongustafson/form-saver) — веб-компонент, который запоминает значения первой вложенной формы и восстанавливает их после сбоя или прерванной сессии.
- [rich-input](https://github.com/bramus/rich-input) совмещает автодополнение и подсветку внутри поля ввода через `<datalist>`, OpaqueRange API и CSS Custom Highlight API.
- [pure-web-bottom-sheet](https://github.com/viliket/pure-web-bottom-sheet) — лёгкий framework-agnostic bottom sheet как веб-компонент на базе CSS scroll snap.

## 📦 JavaScript и сборка

### Parcel 3 переписали на Rust

Вышла альфа [Parcel 3](https://v3.parceljs.org/blog/v3-alpha/): сборщик переписан на Rust и, по замерам команды на холодной сборке React Spectrum, может быть до 100 раз быстрее Parcel 2. Он работает самостоятельным бинарником без Node.js, поддерживает нативные плагины на Rust, Go и Swift, а JavaScript-плагины запускает во встроенном QuickJS.

### JavaScript пробует общее состояние между потоками

Erik Arvidsson исследует, как могли бы выглядеть [многопоточные программы на JavaScript с общими объектами](https://blog.arv.tools/archives/2026/11/02/18.35.20/). Он сравнивает форк [Porffor](https://porffor.dev/), TypeScript-библиотеку с проверкой владения и вариант на основе предложения TC39 о [structs](https://tc39.es/proposal-structs/). Пока это эксперимент, но он хорошо раскрывает компромисс между удобством общего состояния и безопасностью данных.

## ⚙️ Node.js

### В Node.js появился эксперимент с green threads

В Node.js открыт PR с [экспериментальной реализацией green threads](https://github.com/nodejs/node/pull/67288). Это лёгкие воркеры, которые делят небольшой пул потоков ОС, но получают отдельный V8 isolate; API Node.js внутри них пока нет. В замерах автора тысяча таких воркеров заняла примерно 1 ГБ памяти вместо 6,7 ГБ у обычных `Worker Threads`.

Идея ещё очень ранняя, но может быть важна для задач с большим числом изолированных вычислений, где полноценные потоки расходуют слишком много памяти.

### Вышли важные обновления безопасности Node.js

[Ноябрьские security-релизы Node.js](https://nodejs.org/en/blog/vulnerability/november-2026-security-releases) закрывают уязвимости HTTP/2, TLS, `zlib` и модели разрешений в ветках [26.13.1](https://nodejs.org/en/blog/release/v26.13.1), [24.22.3](https://nodejs.org/en/blog/release/v24.22.3) и [22.23.5](https://nodejs.org/en/blog/release/v22.23.5). Семь проблем имеют высокий уровень критичности; самая серьёзная могла позволить удалённому клиенту прочитать память другого подключения. Обновления также включают недавний [фикс Undici](https://github.com/nodejs/undici/releases/tag/v8.12.4).

Если dev-сервер Vite доступен из сети через `--host` или `server.host`, нужно отдельно обновиться до исправленной версии: [уязвимость Vite](https://github.com/vitejs/vite/security/advisories/GHSA-p4f5-76q4-ffq7) позволяет удалённое выполнение кода. [Next.js 16.4.5 и 15.5.29](https://nextjs.org/blog/november-2026-security-release) также исправляют семь проблем, включая утечку данных между арендаторами кэша.

### Что готовит Node.js 27

Luciano Mammino собрал [обзор Node.js 27](https://nodejsdesignpatterns.com/blog/whats-new-in-nodejs-27/): новые iterator helpers, promise-версия `node:net/promises`, виртуальная файловая система без флага и список [breaking changes](https://nodejsdesignpatterns.com/blog/whats-new-in-nodejs-27/#heads-up-nodejs-27-breaking-changes). В ближайшей альфе ожидается включённый по умолчанию [Web Worker API](https://github.com/nodejs/node/pull/65323), а отдельный PR предлагает встроенный модуль [`node:yaml`](https://github.com/nodejs/node/pull/67157).

Отдельно Joyee Cheung перечислила [изменения JavaScript между V8 14.6 и 15.6](https://nodejs.org/en/blog/announcements/notable-v8-changes-from-node-js-26-to-27-alpha): Math.sumPrecise, новые методы итераторов и особенности сортировки, дат и промисов. Это полезная шпаргалка перед переходом с Node.js 26 на альфу 27.

## 🛡️ Безопасность и веб

### Защита от ботов требует проверять последствия

Terence Eden описал [ловушку для ботов, игнорирующих `robots.txt`](https://shkspr.mobi/blog/2026/11/blunt-banhammer-blocks-basic-bots-ballistically/): она отправляет нарушителей в honeypot и затем банит их. Подход снизил расход трафика почти на 90%, но не лишён компромиссов. Другой опыт — год борьбы со скрейперами через [правила Cloudflare](https://patronview.com/news/99-percent-of-my-website-traffic-is-bots/).

- Эксперимент с [«запретными» фразами в тестовом коде](https://utkusen.substack.com/p/tricking-deepseek-into-not-hacking) показал, что некоторые ИИ-агенты отказываются анализировать такой проект. Это любопытное наблюдение, но не надёжная защита.
- Анализ логов в статье [«Мои человеческие посетители были ботами»](https://luna-park.app/blog/my-human-visitors-were-bots) напоминает, почему метрики посещаемости стоит сверять с поведением и серверными данными, а не принимать за чистую монету.
